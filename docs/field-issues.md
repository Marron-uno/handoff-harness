# Field issues

Harness defects found while running real goals. Each entry names where it bites, the workaround used in the run, and the fix. Move an entry to Fixed with the commit that closes it.

Source run: angar-shopify, goals G-1 and G-2 (2026-10-14). Issue 15 was found while fixing the others, in this repository.

## Open

None.

## Fixed

All fifteen closed by the `field-issues` OpenSpec change (`openspec/changes/field-issues/`), version 0.5.0. Each has a regression in `tests/field-issues.test.mjs` named by issue number.

## Requested features

- Open-items ledger: the harness should keep `.harness/reports/open-items.md` itself, so pending work survives a lost session. Seed it at intake from plan holds and defaults marked "for client confirmation", append to it whenever a judge raises a non-blocking finding or a slice leaves something for a human, update it when `goal approve`, `retry` or a human decision resolves an item, and print it in `goal status` and the final report. Today it only exists because the orchestrator wrote it by hand (angar run, 2026-10-14).
- Lightweight follow-up path: a one-line visual fix (G-5 in the angar run) cost about $8.50 because it needed a full goal with intake, critic, reviewer and reconciler. Offer a `harness quickfix` mode (one slice, one combined judge, no reconcile) for changes under a small diff budget. Since 0.5.0 a done goal is dormant, so a one-line fix can also be made by hand on a new branch without a goal at all.
- Progress bar: show slices done, percent, time left and budget use in `goal status`, a `harness progress` command and the status line. Spec written during the angar run (`progress-bar-task.md` in that session's scratchpad); copy it here when work starts.
